<!-- sdlc:auto:start overview -->
Hello App is a minimal demo web app generated by the Quorq AI SDLC platform, consisting of a FastAPI backend and a Vite + React 19 frontend in a single repository. The only feature is a public Hello page that fetches a greeting from the backend's GET /api/hello endpoint. The backend ships with a health check and stub infrastructure (SQLAlchemy models, Pydantic schemas, CORS, SQLite default database), while the frontend is an SPA built with React Router, Tailwind CSS, and seeded sample data not yet wired to real endpoints.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js 20+
- Python 3.12+
- pip
- Docker and Docker Compose (optional, for PostgreSQL and containerized backend)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. git clone the repository and cd into the project root
2. cd frontend && npm install
3. cd ../backend && pip install -r requirements.txt
4. Optionally, from the project root run docker compose up -d db to start a local PostgreSQL 16 instance on port 5432
5. From the backend directory, run uvicorn app.main:app --reload to start the API on port 8000
6. From the frontend directory, run npm run dev to start the Vite dev server on port 5173
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend follows a one-router-per-component, one-route-per-endpoint architecture; generated routes return typed StubResponse placeholders until implemented
- Backend uses SQLAlchemy 2.0 declarative models inheriting from a shared Base, with tables created at startup via Base.metadata.create_all (no Alembic migrations yet)
- Backend defaults to SQLite (sqlite:///./app.db) unless DATABASE_URL env var is set, so it runs with no external database
- Frontend uses TypeScript with path alias '@/' mapping to './src/'
- Frontend screens render seeded sample data; the apiFetch seam in src/lib/api.ts is the integration point for wiring real backend calls
- API base URL and project ID are injected at build time via Vite env vars VITE_API_BASE_URL and VITE_API_PROJECT_ID, falling back to localhost:8000
- Session tokens are stored in localStorage under 'session_token' and sent as Bearer headers by apiFetch
- CORS origins default to Vite dev server URLs (localhost:5173, 127.0.0.1:5173) unless ALLOWED_ORIGINS env var is set
- Backend container runs as unprivileged user (uid 10001) with a health check on /health
- Frontend tests: Vitest for component tests scoped to src/**, Playwright for e2e tests in e2e/**
- Linting: ESLint for frontend, Ruff for backend; Prettier for frontend formatting
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Backend fails to start with a database connection error | The backend defaults to a local SQLite file. If DATABASE_URL is set to a PostgreSQL server that is not running, either start the database via 'docker compose up -d db' or unset DATABASE_URL to fall back to SQLite. |
| Frontend API calls fail with CORS errors in the browser | The backend allows origins from ALLOWED_ORIGINS env var or defaults to localhost:5173/127.0.0.1:5173. If the frontend runs on a different origin, set ALLOWED_ORIGINS to include that origin on the backend. |
| Playwright e2e tests fail because the backend is not running | Without E2E_BASE_URL set, Playwright automatically boots the backend from ../backend/.venv. Ensure backend dependencies are installed in backend/.venv first, or start the backend manually and set E2E_BASE_URL. |
| pytest cannot import app modules from the backend directory | pytest.ini sets pythonpath to '.' so run pytest from the backend/ directory, not the project root. |
| npm run build succeeds but deployment fails type checking | npm run build does not run tsc. Run 'npm run typecheck' separately and fix type errors before deployment. |
<!-- sdlc:auto:end troubleshooting -->
