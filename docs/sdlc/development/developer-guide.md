<!-- sdlc:auto:start overview -->
Hello App is a minimal demo web application with a single feature: a public Hello page that displays a greeting fetched from the backend endpoint GET /api/hello. It is generated by the Quorq AI SDLC platform and consists of a Vite + React 19 SPA frontend and a FastAPI 0.115 backend in one repository. The backend uses SQLAlchemy with a SQLite default (PostgreSQL 16 in docker-compose), and the frontend uses Tailwind CSS and React Router. The app serves as a smoke test of the delivery pipeline, including a GitHub Actions deployment workflow that pushes a Docker image to AWS ECR and deploys the frontend to AWS Amplify.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js 20+
- Python 3.12+
- Docker and Docker Compose (optional, for PostgreSQL and containerized backend)

<!-- sdlc:auto:start setup -->
1. git clone the repository and cd into the project root
2. cd frontend && npm install
3. cd ../backend && pip install -r requirements.txt
4. Optional: from the project root run docker compose up -d db to start PostgreSQL 16
5. cd backend && uvicorn app.main:app --reload to start the API on port 8000
6. cd frontend && npm run dev to start the Vite dev server on port 5173
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Frontend uses TypeScript with strict mode enabled (noImplicitAny and strictNullChecks relaxed), path alias @/* mapping to ./src/*
- Frontend screens are one module per approved screen in src/screens/, wrapped by the AppShellLayout navigation shell in App.tsx
- Frontend tests live beside the components they cover; Vitest handles src/** tests, Playwright handles e2e/** specs
- Backend follows a one-router-per-component pattern under app/routers/, with Pydantic schemas in schemas.py and SQLAlchemy models in models.py
- Backend uses ruff for linting and formatting (ruff.toml config); pytest.ini sets pythonpath and testpaths
- Backend defaults to SQLite (DATABASE_URL env var overrides to PostgreSQL or other); tables auto-created on startup via Base.metadata.create_all
- CORS is configured via ALLOWED_ORIGINS env var, falling back to localhost dev origins
- The frontend API client (api.ts) sends a bearer token from localStorage session_token or the baked-in VITE_API_PROJECT_ID; API_BASE_URL defaults to http://localhost:8000
- All GitHub Actions are pinned to specific commit SHAs, not movable tags
- Dockerfile runs as an unprivileged user (appuser, uid 10001) with a Python stdlib healthcheck on /health
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Backend fails to start with a database connection error | The backend defaults to SQLite (sqlite:///./app.db). If DATABASE_URL is set to a PostgreSQL URL, ensure the database server is running (docker compose up -d db) and that DATABASE_URL is correct. |
| Frontend API calls fail with CORS errors in the browser | The backend CORS middleware allows origins from ALLOWED_ORIGINS env var, falling back to localhost:5173 and 127.0.0.1:5173. Set ALLOWED_ORIGINS to include your frontend origin if using a different dev server port or domain. |
| Playwright e2e tests fail because the backend is not running | Playwright config boots the backend from ../backend/.venv/bin/python automatically. Ensure backend dependencies are installed in backend/.venv, or run the backend manually before setting E2E_BASE_URL. |
| npm run build succeeds but the deployed app calls localhost instead of the real API | VITE_API_BASE_URL is baked into the bundle at build time. The deploy workflow sets it; for local production builds, set VITE_API_BASE_URL before running npm run build. |
| pytest cannot import app modules from the backend directory | pytest.ini sets pythonpath = . so a bare pytest from backend/ can import app. Ensure you run pytest from the backend/ directory, not the project root. |
<!-- sdlc:auto:end troubleshooting -->
